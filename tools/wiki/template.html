Writing code mods for PaperBoat

PaperBoat mods are C source files packed into an .o2r archive. The game compiles them with TinyCC when it starts, so a mod is plain text you can read, and the same archive works on every platform that runs code mods. This wiki covers how to build one and every function, structure and event a mod can use.

Guide

Your first mod

Start from workspace/template, inside a PaperBoat checkout or the mod SDK zip. The SDK has the same layout and holds only what mods are built against: the headers, the mod tools, the template and the online example. A PaperBoat build writes it with cmake --build build --target mod_sdk.

  1. Copy the template

    Copy workspace/template to workspace/my-mod and change project() in its CMakeLists.txt; the archive is named after it. Fill in manifest.json.

  2. Write the entry points 
    #include "mod.h"
#include "port/hooks/Events.h"
#include <stdio.h>

static void LogCoins(IEvent* event) {
    OnCoinsChanged* coins = (OnCoinsChanged*) event;
    printf("Coins: %d -> %d\n", coins->before, coins->after);
}

MOD_INIT() {
    REGISTER_LISTENER(OnCoinsChanged, EVENT_PRIORITY_NORMAL, LogCoins);
}

MOD_EXIT() {
}
  3. Build the archive
    cmake -B build -S .
cmake --build build --target package_mod

    You need CMake 3.10 or newer and Python 3. Pillow is only needed for .png files used with #asset.

  4. Install it

    Copy the .o2r into PaperBoat's mods/ folder and start the game. Compiler errors appear under Settings › Mod Menu. Reload Scripts there rebuilds every mod without restarting.

How the build packages a mod

The build merges each .c file in src/ with every game and libultraship header it includes into one self-contained file under output/dist/, and lists those files in build.gen. Conditionals are evaluated with the defines the game compiles mods with, so only the headers a mod uses are inlined; checks on the platform are left for TinyCC on the player's machine. A mod never depends on headers being present there. Everything from one source file ends up in one translation unit: mark helpers static, and avoid names the game already uses, such as AddItem or Mark.

mod.h defines MOD_INIT and MOD_EXIT, routes malloc and free through the engine's allocator, and provides CALL_FUNC for calling into another mod. Name event listeners after what they do: an event's name is already its struct type.

Guide

Loading, reloading and cleanup

At startup the game mounts every enabled mod archive in order, compiles each mod's sources behind a progress popup, then calls ModInit in dependency order, after every event is registered. When a mod unloads, on exit or on Reload Scripts, the game calls its ModExit and then releases everything the mod registered: items, moves, messages, maps, battles, sounds, puppets, scripts it started, event listeners, Mods menu pages and widgets, and GUI callbacks. Reloads happen between game frames, never in the middle of one.

So MOD_EXIT is optional. Use it only to undo what the mod set up some other way, such as a game variable it changed directly.

The Mod Menu

Settings › Mod Menu lists the installed mods, enabled and disabled, with a code icon before each code mod (one whose manifest names a main or binaries) and a brush before each shader mod (one with shaders passes or materials). Each enabled code mod also shows whether it is signed and whether its code loaded, with the compiler's message or the reason it was skipped on hover. After Edit, mods can be turned on and off and reordered: mods higher in the list are mounted later, so their files replace those of mods below them, and their code initializes later; dependencies always initialize first. Changes apply on Apply & Restart. A mod's own pages go under the Mods header of the menu, next to Satella.

Dependencies

A version range is a list of comparisons separated by spaces or commas: >=, >, <=, < and =. A version without an operator is a minimum. A mod whose dependency is missing, failed to build or falls outside the range is skipped with a notification, along with every mod that depends on it.

Content ids and saves

Items, moves, messages and battles have an id string such as "mymod.mega_mushroom". The game gives each a number for the session from the ranges below. Save files record the id of every mod item they hold, and the mod map they were saved in. When a save loads with different numbers, because mods were added, removed or loaded in another order, its items are renumbered to match. A save holding content from mods that aren't loaded shows a notification naming them; that content reads as nothing until the mods are back, and keeps its id when saved again.

Keep ids stable. Never reuse an id for different content, and never change the id of content players may already own. Store ids, not numbers, in your own save data.

Values a mod keeps for a save file go through savedata.h. Settings that belong to the player rather than the file go through cvar.h.

Assets

C_ASSET(name, path) declares one of the game's own assets by its path in the game archive. texture.h reads files and textures from any archive, the mod's included. #asset converts a file next to the source into the game's formats when the mod is built:

static const u8 sIcon[] = { #asset "textures/icon.png" CI4 };
static const u8 sIconPalette[] = { #asset "textures/icon.png" CI4_PAL };
FormatUse
(none), RGBA32Full colour, decoded when the game loads it.
RGBA165 bits per channel and 1 bit of alpha.
CI4, CI8 and CI4_PAL, CI8_PAL16 or 256 colours, and their palette. Item icons are CI4.
I4, I8, IA4, IA8, IA16Greyscale, with or without alpha.

A map a mod adds with world.h loads its shape, hit and texture assets under its own name, from the mod's archive, as the game's maps do. Sounds and music come from WAV, MP3 or FLAC files through sound.h.

Guide

Text and messages

Text is UTF-8, with \n for a new line and tags for the game's control codes:

int32_t hello = C_RegisterMessage("mymod.hello", "Hi, Mario!<<NEXT>>Nice day for it.");

The message ID works anywhere the game takes one: item and move names, EVT dialogue such as SpeakToPlayer, tattles. C_OverrideMessage replaces one of the game's own messages until the mod unloads.

Guide

EVT scripts

Mods write EVT scripts with the game's own EVT_ macros, and their API_CALLABLE functions are called by address from those scripts. Start a script with C_StartScript while the game runs, for example from an OnMapReady listener: the game clears every script when a map loads. A mod's scripts stop before it unloads.

iOS, WebNoA mod's files and assets load, its code doesn't. Saves made with mod items keep them.

On Windows a mod can only read or write a game variable declared extern_s, which becomes __declspec(dllimport) when TinyCC builds a mod. gPlayerData, gPlayerStatus, gGameStatus, gItemTable, gMoveTable and the other globals mods use most already are; functions don't need it. Unsigned mods load and are marked as such; archives can be signed with external/libultraship/tools/sign.py.

Guide

Online features with Satella

Satella is the online service PaperBoat connects to when it starts, at wss://satella.net64.dev. It gives the game the keys trusted mods are signed with. Each install has a player key it proves to Satella on every connection, so every message says which player sent it (online.h). Mods go online through relay channels and rooms for messages between players, the player store for values kept for one player, and the channel store for values shared by everyone on a channel. Puppets show other players in the map.

FeatureWho readsWho writesLimit

Permission comes first

A mod registers each channel or room group with a name and one sentence about what it is for. The player is asked once with an Allow / Deny prompt, and the answer is kept in permissions.json; Mods › Satella lists every answer and changes it. Until they allow it, sending and writing return FALSE. permissions.h gives a mod the same prompt for its own needs.

Other players in the same map

static void OnMessage(const char* group, const char* room, const char* sender, const char* data,
                      uint32_t size, int direct) {
    if (size == sizeof(C_PlayerPose)) {
        C_SetPuppetPose(PuppetFor(sender), (const C_PlayerPose*) data);
    }
}

static void SendPose(IEvent* event) {
    C_PlayerPose pose;
    if (C_GetPlayerPose(&pose) && C_JoinRoom("paperboat.online", pose.map)) {
        C_RoomSend("paperboat.online", pose.map, (const char*) &pose, sizeof(pose));
    }
}

workspace/online is the whole example: one room per map, about 15 poses a second, and a puppet for every other player in the room. Every callback runs on the game thread, as the mod that asked, and is skipped if the mod has unloaded by then.

Where it works

Satella is in every build that runs code mods, desktop and Android, and players can turn it off under Mods › Satella, which also takes the address of a server of their own. Without it, or on iOS and the web, these calls return FALSE and nothing arrives, so a mod should treat online features as optional.

Listening to events

The game fires events at the points mods are likely to care about. A listener receives an IEvent* to cast to the event's own struct. Events fire on the game thread.

static void SkipFpCost(IEvent* event) {
    event->Cancelled = true;   // moves cost no FP
}

MOD_INIT() {
    REGISTER_LISTENER(OnPlayerFPChange, EVENT_PRIORITY_NORMAL, SkipFpCost);
}
KindWhat a listener can do
cancellableSet event->Cancelled = true. Each event says what cancelling does: skip the game's code, use the listener's result, or skip one element.
Pointer fieldsFields typed as pointers, like int32_t* damage, let a listener change what the game uses by writing through them.
polledFound by comparing the game with a snapshot once per frame while a file is in play: they fire on the frame after the change.

Listeners run from EVENT_PRIORITY_LOW to EVENT_PRIORITY_HIGH; among the same priority, the one registered last runs first. UNREGISTER_LISTENER(Event, id) removes a listener while the mod runs.
